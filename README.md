# Lichii 自动备份镜像

本仓库是 [Lichii](https://github.com/zortos293/Lichii) 模拟器项目的非官方自动备份镜像，使用 GitHub Actions 定期同步上游仓库的源代码、分支、标签及发布文件。

建立本仓库的目的是保留项目的代码历史与发布版本，方便后续查阅、下载和研究。

## 项目来源

- **原始项目：** https://github.com/zortos293/Lichii
- **备份仓库：** https://github.com/ddddng/Lichii
- **同步工作流：** [sync-lichii.yml](https://github.com/ddddng/Lichii/blob/sync-lichii/.github/workflows/sync-lichii.yml)

本仓库并非 Lichii 官方仓库

## 备份内容

通过 GitHub Actions 自动同步以下内容：

- **源代码：** 备份上游仓库的代码及 Git 提交历史。
- **分支：** 保留上游各分支的名称与内容。
- **标签：** 同步上游的 Git 标签。
- **发布版本：** 同步 Releases 的版本名称、说明及预发布状态。
- **发布附件：** 下载并备份各版本的附件，包括上游提供的可执行文件等。
- **最新版本：** 同步上游标记的最新正式发布版本。

## 同步机制

本仓库通过 GitHub Actions 自动运行备份任务。

- **自动同步：** 每 6 小时执行一次。
- **手动同步：** 可以通过 Actions 页面手动触发。
- **工作流更新：** 修改同步工作流文件时也会触发备份。

同步过程中会检查已有发布版本及附件，尽量避免重复上传未发生变化的文件。

### 工作流隔离

为了防止上游项目的 GitHub Actions 工作流在备份仓库中被意外执行，同步时会将上游提交历史中的：

`.github/workflows/`

迁移至：

`.github/upstream-workflows/`

因此，镜像保留了上游的代码内容和历史结构，但部分 Git 提交哈希可能与原仓库不同。

本仓库自己的备份工作流独立保存在 `sync-lichii` 分支中，该分支也是仓库的默认分支。

## 下载与使用

可以通过以下方式获取备份内容：

- **查看源代码：** 在仓库的分支列表中选择需要的上游分支。
- **下载发布版本：** 前往 [Releases 页面](https://github.com/ddddng/Lichii/releases) 获取已同步的版本及附件。
- **查看历史版本：** 通过标签或提交历史查找对应的代码版本。

本仓库以备份和归档为主要目的。
